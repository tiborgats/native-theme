# v0.7.1 → 0.8.0 — M1a design: the new model built in `next`

The engineering plan for [the plan](todo_v0.7.1_model-completeness-plan.md)'s M1a (drafted 2026-10-30, decisions by
the orchestrator below). It decides no part of the model: the specification does. Archived with the plan at M6.

## 1. Architecture of `next`

**Module tree** (`native-theme/src/next/`, declared `#[doc(hidden)] pub mod next;` in `lib.rs`):

| File | Holds |
|---|---|
| `mod.rs` | the re-exports (the shape that becomes the crate root at the switch) |
| `units.rs` | `Px`, `Ms`, `Deg`, `Fraction`, `Scalar`, `FontSize`, `Length`, `Sides`, `Axes`, `Rect`, `Size`, `Point`, `ViewBox` |
| `key.rs` | `Key`, `KeyError`, `key!` (a `macro_rules!` with a `const fn` grammar check, so a bad literal fails to compile) |
| `color.rs` | S2.1's `Color`, its four TOML literal forms, `to_srgb8_clamped`, `to_display_p3`, `composite_over` |
| `value.rs` | `Value<T>`, `SchemeMap`, `SurfaceMap` |
| `expr/{parse,ty,eval,arith}.rs` | S2.2: the grammar, the typing table, totality, the model's own arithmetic |
| `blocks/{paint,outline,shadow,transform,motion,text,icon,focus,part_style}.rs` | S2.3–S2.11 |
| `roles.rs`, `tokens.rs`, `inputs.rs` | S3; S4 (the slice's groups); S9's `InputBases`, `InputValue`, `Accent` |
| `selector.rs`, `declare.rs` | S7; S10 |
| `toml/` | S11: `Layer::from_toml` and the `when` and `declare` readers |
| `validate/{checks,combos}.rs` | S12 |
| `resolve.rs`, `query.rs`, `theme.rs` | S8; S8's query and S9.4's scaling; S16's subset |
| `error.rs` | the error types |
| `widgets/gen_*.rs` | generated; never edited by hand |
| `registry.rs` | the field-path registry, assembled from the derive's tables |
| `platform/` | S2.2's platform functions, one file each |
| `presets/mod.rs`, `presets/*.toml` | the bundled presets (`include_str!`) |

**Values and expressions.** The `Expr` AST is `Lit | Ref | Call(Func, Vec<Expr>)` with a hand-written
recursive-descent parser (no new dependency); typing happens when a layer is added (S12) and yields a typed `Expr`;
evaluation is infallible, through an `Env` trait (roles, tokens, inputs, `base`, element data,
`part.`/`widget.`/`values.`, metrics), so expressions are testable without the full model. Lazy patches over a
reference (S2.2) are an internal `Composed { reference, patches }`, not a public variant.

**Patch and resolved types** are generated by the derive: `<T>Patch` (every field an `Option`; a struct block
`Set | Fields`; a paint `Set | Append`), `Resolved<T>` (each `Value` to an `Option`, or `Option<Length>` where `Auto`
is allowed). Merging follows S6.1: a map merges by key, any other list is replaced whole.

**Rules and layers.** `Rule { selector, body: Colors | Tokens | Part | Values }`; a `Layer` is bases, `for_preset`
and rules. **Resolver order:** preset, reader or stand-in, application layers, the accent layer; all bases merge
first (colours by the scheme in force, inputs by contrast), then the Colors and Tokens rules choose expressions, then
each part keeps its base plus the rules whose conditions hold. `WindowState` records the inputs so `resolve`
classifies the `Change`.

**Query:** `ResolvedTheme::style`, `values<W>`, `tokens`, `role`, `size_classes`, `data_needs`; `Scope` is owned;
right-to-left mirroring in the query (S2.4). **`Theme`** owns the stack, the conditions and the accent, and
re-validates the whole stack on every mutation.

**`ThemeParts` and `generate_widgets.py`.** The generator reads the catalogue through `spec_catalogue.py`; the
enabled units are listed in `scripts/widget_units.toml` (`slice = ["button"]`). Per widget it writes
`widgets/gen_<widget>.rs` (the derive input `struct ButtonTheme` with one `#[part(root?, element?, parent = …,
fields(…), may_be_absent?)]` per part, `ButtonValues` with `#[value(may_be_absent?, auto?)]`, the catalogue's own
enums) and `widgets/gen_index.rs` (`WidgetKind`, `Variant`, `TypedPart` over the enabled units, `WidgetsPatch`,
`WidgetValuesPatch`, the registry list); its output goes through `rustfmt` from stdin, and `--check` compares bytes.
`#[derive(ThemeParts)]` is a new module of `native-theme-derive` beside `ThemeWidget`: on a widget it expands to the
part enum, the patch, the marker trait impl, the field sets and static `FieldInfo { path, ty, may_be_absent, auto }`
tables; with `#[parts(block)]` it expands blocks the same way.

**Presets** are TOML (S11) under `next/presets/`, included with `include_str!`, read by the generic `toml::Table`
reader and walked against the registry (not serde derive on the model): the only way to handle unit suffixes,
shorthands, refusing unknown keys with their TOML path and collecting every `Problem`. Serde stays for unit-variant
enums. `toml`'s `preserve_order` feature is turned on so keyed maps keep a deterministic order.

**Errors** (`error.rs`): `LayerError`, `Problem { path, kind }`, `ProblemKind` (one variant per S12 item),
`ThemeError`, `ReaderStatus`, `ReaderFailure`, `KeyError`, each with `Display` and `Error`; all enums exhaustive;
every public struct `#[non_exhaustive]` except S1's two lists (S21.2).

**The facts gate** (`native-theme/tests/facts_gate.rs`, helpers in `tests/facts_gate/`) reads
`concat!(env!("CARGO_MANIFEST_DIR"), "/../docs/facts")` at run time and reaches the crate through a doc-hidden
`next::gate` module (`parse_when`, `parse_value_for(path)`, `holds(path)`, `eval_in(scope, expr)`). Its core is
`run(facts_root, presets)`, run once over fixtures (`tests/fixtures/facts_gate/`, where synthetic values are allowed)
and once over the real tree with `PresetId::all()`. Font metrics come from a fixed, documented stub in the gate's
source, as the perturbed run's colours do.

**Platform functions**: one file per function in `next/platform/<fn>.rs`, each with
`native-theme/tests/vectors/<fn>.tsv` and a test `vectors_<fn>` in `tests/platform_vectors.rs`; the evaluator's
function table calls them.

**Dependencies**: no new crate.

**Constraints for every implementer.** `scripts/check_strict_panic.sh` denies `indexing_slicing`,
`arithmetic_side_effects` and `modulo_arithmetic` in library code: use `.get()`, `checked_*`, `checked_rem_euclid`.
`missing_docs` does not fire inside a `#[doc(hidden)]` module, so task 1 gates it: `#[cfg_attr(not(nt_next_docs),
doc(hidden))]`, `unexpected_cfgs` declared in `[lints]`, and a `check_release.sh` step `cargo rustc -p native-theme
--lib -- --cfg nt_next_docs -D missing-docs`.

## 2. Task sequence

Code tasks run one at a time on `v0.8.0-rc1`, in the main checkout (a worktree would build a separate build folder).
Each leaves `scripts/check_release.sh --commit` green and today's crate untouched. A fresh reviewer per task checks,
besides its own points: no panic, indexing or `unsafe`; no constant that is not the spec's definition; every
normative name exactly as the spec writes it; `#[non_exhaustive]` per S1 and exhaustive enums; docs on every public
item; no dead code; no file outside `next`, the derive and the scripts changed.

## 3. Where the facts enter

Tasks 15 and 16 need every slice key, `state-models.toml` and the declarations for the gnome and macos directories
(spike M does not cover the accent and contrast passes, focus, mixed or other bezels: they block task 16 until a probe
pass measures them). Task 13's function list follows the lanes. Tasks 1–14, P1 and P2 are built and tested on
fixtures before any fact; enabling `button` before any preset exists satisfies *One rule for every model field*
vacuously, and each preset then states every field the model holds.

## 4. Decisions (the orchestrator, 2026-10-30, by the specification and the plan)

1. **Placement inside `button`** (`menu_placement: Placement`, `scaffold_placement: Value<Placement>`, while M1a is
   "S8 without S13"): task 6 defines S13's data types (no `place()`), and the generator takes a per-value deferral
   (`deferred = { button = ["menu_placement", "scaffold_placement"] }`) until M3's placement unit. A class 2 change
   to S6.1's unit definition (a unit may defer named values), recorded in the ledger's queue.
2. **`ScrollDecay`** ("closed: one variant per platform deceleration … written in the value phase"): `Behavior.scroll`
   and `ScrollPhysics` are staged to the `scroll_view` unit (an empty enum would force a false `absent`).
3. **`MaterialShape`** ("the value phase writes the list from the file"): an uninhabited enum in M1a, so the two
   presets state `shape = "absent"`, which the spec allows; filled at M1b.
4. **Untriggerable errors** (`SchemeNotInPalette`, `PaletteNotForPreset` need `apply_palette`): added in M1b with their
   triggers, so the refusal test stays exhaustive.
5. **S12's exact check**: enumerate only the atoms the rules reaching one path name, deduplicating rule-applicability
   vectors, under S12's exclusions; task 9 measures the cost (a scale risk for M3).
6. **`may_be_absent` per preset** (the catalogue writes "all but `ios-*`, `kde-breeze`", S6.3 keys per path): the
   generated table holds the union per path; which preset truly draws nothing the facts gate checks.
7. **A fact naming a preset `PresetId` does not hold yet**: the gate treats its `when` as not holding and reports the
   count.
8. **`check_facts.py`'s existing presets** move to `native-theme/src/next/presets/` (P1) before the lanes' facts are
   merged.
